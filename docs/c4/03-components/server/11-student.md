# Component: student

The student handler answers `POST /api/student`. It is the server side of a student's profile, mindmap and the actions the browser reports: signing in, opening a module, switching mode or layout, and running code. It never reads or writes evidence, so none of these actions change mastery.

> [C4 index](../../README.md) / Level 3: Components / Turn and admin server

The handler receives one [activity recorder](12-activity-recorder.md), the same one the turn handler receives. A message, submission or quiz answer is recorded on the turn. A run is recorded here, and the payload never includes the code. Profile changes, notes and mindmap moves are recorded here too. A request marked as a preview writes nothing.

Profile pictures go in the private `student-files` bucket, one folder per student: the picture at `portrait`, and each note's one optional image at `notes/<noteId>-<uuid>`, its path kept on the note (`mindmap_notes.image_path`). `note_image_changed` takes a JPEG, PNG or WebP image (the browser sends WebP shrunk to 1024 px) to set or replace it, or `null` to remove it; the old file is deleted and the change is recorded as `note_changed`. Each note in the answer carries a signed `imageUrl` or null. The browser receives a signed URL. The student number is read with the profile and cannot be changed on this handler. The profile also carries the campus: `campus_chosen` sets it once for a student who has none (the store refuses a second choice) and `profile_changed` refuses any campus. A student with no campus is refused the study events (`module_opened`, `mode_switched`, `layout_switched`, `code_run`) with 403 until they choose, and the workspace page shows `CampusStep` over everything else.

Notes, links and module positions are stored per student and course. A note, a link or a module position is written on its own, so saving one does not rewrite the others. A note links to a module or to another note; linking the same target again changes nothing, and a note cannot link to itself. A note always keeps at least one link: `note_created` carries the first link and the store writes the note and the link in one transaction (`insert_mindmap_note`), the handler refuses a new note with no valid link, and it refuses `note_unlinked` for a note's last link. Events that only change the mindmap return the profile without a signed picture URL; `open`, `signed_in` and `profile_changed` still sign it. Deleting a note deletes the links that point at it. A note colour must be one of the palette tokens in `shared/mindmap.ts`. Row-level security lets a student read only their own rows. Agents are not given the notes.

The workspace reads positions on open. A legacy device arrangement can be imported before the student has saved an account position or reset this course’s arrangement. Reset clears the saved positions and records the reset for the account in the same transaction. An import or reset that changes positions records `mindmap_moved`.
