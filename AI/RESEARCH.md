# Self-harm content signals in English prompts

This offline proof of concept tests whether one submitted prompt can be scored for the historical OpenAI self-harm moderation label. A score reflects textual evidence for that label. Assessing a student's personal safety, intent, or need for support requires context beyond the experiment's input and labels. The experiment uses public benchmark text and independently authored synthetic evaluation cases. [OpenAI dataset taxonomy](https://github.com/openai/moderation-api-release#evaluation-dataset-for-the-paper-a-holistic-approach-to-undesired-content-detection), [OpenAI Moderation guide](https://developers.openai.com/api/docs/guides/moderation#content-classifications)

## Dataset and label

OpenAI published `data/samples-1680.jsonl.gz` as a test set for Markov et al.'s moderation research and describes the release as labeled Common Crawl data. Each record contains a `prompt` and may include a binary `SH` field. The pinned file has 1,680 records, with 51 `SH = 1`, 1,396 `SH = 0`, and 233 missing `SH`. The dataset README treats missing labels as unknown. Excluding them leaves 1,447 labeled examples and 3.52% positives before deduplication. The resulting split is an evaluation within a repurposed public benchmark. [OpenAI release announcement](https://openai.com/index/new-and-improved-content-moderation-tooling/), [Markov et al.](https://arxiv.org/abs/2208.03274), [dataset README and pinned archive](https://github.com/openai/moderation-api-release/tree/d3938df6ce8b06c2907f92c6084d8192da61b9aa)

The historical `SH` category covers content promoting, encouraging, or depicting self-harm. The current API guide also defines distinct `self-harm/intent` and `self-harm/instructions` categories. The archive supplies only the broader `SH` label. Broad positives can include depictions without a first-person disclosure, and the archive has no separate labels for help-seeking, quoted material, or context from an earlier turn. [OpenAI dataset taxonomy](https://github.com/openai/moderation-api-release#evaluation-dataset-for-the-paper-a-holistic-approach-to-undesired-content-detection), [OpenAI Moderation guide](https://developers.openai.com/api/docs/guides/moderation#content-classifications)

The release repository carries an MIT license with a notice-retention condition for covered copies. Its archive contains sensitive web text across multiple categories, including graphic violence and sexual content involving minors. The experiment decompresses in memory, publishes aggregate counts and metrics, and saves fitted parameters as numeric arrays. The released archive and its prompt text stay out of the repository and experiment outputs. [OpenAI repository license](https://github.com/openai/moderation-api-release/blob/main/LICENSE), [OpenAI dataset taxonomy](https://github.com/openai/moderation-api-release#evaluation-dataset-for-the-paper-a-holistic-approach-to-undesired-content-detection)

## Synthetic alternative and domain shift

Sword Health's MindGuard training set contains 6,115 fully synthetic labeled user turns in therapeutic dialogues under CC BY-NC-SA 4.0. A language-model judge assigned its turn-level labels with conversation history, including a category for potential self-harm risk. A prompt-only experiment could score the user message alone as a separate domain-shift check. The missing history and differences in task definitions would make disagreements hard to attribute, and scores could reflect the generator's wording or the judge's labeling patterns. [MindGuard dataset card](https://huggingface.co/datasets/swordhealth/MindGuard-trainingset), [Farinhas et al.](https://arxiv.org/abs/2602.00950)

For the course setting, a small independently authored English set can probe indirect disclosures, ordinary assignment frustration, quotation, help-seeking, and academic discussion of the topic. Keeping these cases out of training and threshold selection makes them an independent check. Web excerpts, synthetic therapeutic dialogue, and learner turns could differ in phrasing, length, context, and prevalence. A small curated set can expose misses and false alarms, while its case mix gives no estimate of the prevalence or performance in real student traffic. [Markov et al., discussion of distribution shift](https://ojs.aaai.org/index.php/AAAI/article/download/26752/26524), [MindGuard dataset card](https://huggingface.co/datasets/swordhealth/MindGuard-trainingset)

Submitted text directly matches the unit of labeling and works with the offline dataset. Keystroke timing would require collecting key-press and release events and obtaining independently labeled data tying those behavioral measurements to the target. Research on detecting identity from keystrokes addresses a separate task. [Kaluarachchi et al., keystroke dynamics across devices](https://arxiv.org/abs/2310.04059)

## Reproducible evaluation

1. Pin the upstream archive to commit `d3938df6ce8b06c2907f92c6084d8192da61b9aa` and verify its SHA-256 against `ef3f7de86ee394fe337b0a566ba4b9c7db058f3caa8d6a4a0006138b663ab9a8`. Use only explicit `SH` labels. Deduplicate after text normalization before a seeded stratified 80/20 split so exact normalized duplicates cannot cross the split. Pin Python dependencies and record the split seed and model settings. [Pinned dataset](https://github.com/openai/moderation-api-release/blob/d3938df6ce8b06c2907f92c6084d8192da61b9aa/data/samples-1680.jsonl.gz), [scikit-learn on reproducibility and leakage](https://scikit-learn.org/stable/common_pitfalls.html)
2. Fit a sparse pipeline using character n-gram counts from `HashingVectorizer`, `TfidfTransformer`, and class-weighted `LogisticRegression`. Hashing keeps the exported model free of a literal vocabulary, with feature collisions as a tradeoff. Fit IDF and the classifier within each training fold. Select a score threshold using stratified out-of-fold predictions on the training partition, refit the pipeline on that partition, and evaluate the held-out 20% with frozen settings. [HashingVectorizer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.HashingVectorizer.html), [TfidfTransformer](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfTransformer.html), [LogisticRegression](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.LogisticRegression.html), [scikit-learn threshold tuning](https://scikit-learn.org/stable/modules/classification_threshold.html)
3. Report the precision–recall curve and average precision (AP) from the continuous held-out scores. AP weights precision by changes in recall. Trapezoidal PR-AUC uses linear interpolation and can give a different answer, so name the statistic explicitly. Report the held-out positive count and prevalence, which is the reference precision for a constant score. Accuracy alone can obscure a complete failure to identify positives. An all-negative classifier would be 96.5% accurate on the labeled archive before deduplication. [scikit-learn AP definition](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html), [Saito and Rehmsmeier on precision–recall under imbalance](https://doi.org/10.1371/journal.pone.0118432)
4. At the selected threshold, report true positives, false positives, true negatives, false negatives, precision, recall, and F1. Those counts show how many labeled examples the operating point misses and how many additional prompts it flags. With around ten positive examples in a fifth of the labeled archive, one decision changes recall by roughly ten percentage points. Report the synthetic set separately and interpret both scores in the context of their own label mix. [scikit-learn classification metrics](https://scikit-learn.org/stable/modules/model_evaluation.html#classification-metrics), [precision and recall on imbalanced test data](https://proceedings.mlr.press/v206/shang23a.html)
